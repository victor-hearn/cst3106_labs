Yahtzee Game Design Documentation

The following is the design details for the Yahtzee game built to be played on a webpage. It outlines the rules of the game, as well as the colours, fonts, specific designs and static HTML/CSS mockups of the page.

The rules for this game are primarily based on the Hasbro-owned version of Yahtzee, with slight adjustments to the scoring rules from the European-based version of Yatzy.

General Design Idea: Made to look like it is being played at home on the dining room table. The game should feel comfortable, like it is being played for family game night.
Note that despite being made to look like family game night, the page remains a single player version of the game.

Overview of the Game

Yahtzee is a game of dice, which has an element of both luck and strategy.

Rules

Rounds

  • Each round the player may roll the dice up to three times.
  • After each roll the player may choose to hold specific dice. These dice remain held until the next round begins.
  • After the player's third roll they must choose an empty box on the scorecard to fill in their score.
  • If the dice combination does not align with any empty boxes, the player must choose a box to fill with a 0.
  • The player may choose to fill a box with their score after their first or second roll if they desire, thus ending the round early.
  • Each box may only be used once, and the game ends when all 13 boxes are filled.

Scoring

Final Score

When all 13 boxes are filled, the player's final score is the total of the upper section, plus the bonus, plus the total of the lower section.

Design System

Colour Palette

Most of the page is made using images. This gets much closer to the "game night at the kitchen table" vibe than would be possible using only traditional colours.

Colour palette
Colour Use
Black (#000000) Most text, most shadows, pips
White (#ffffff) Small inset shadow on pips
#000050 Score text
#fcf7eb Dice
#F9FBFF Paper background
Reasoning

Black: Most of the time printers use black ink for text and tables. The pips on the dice most people own are black. Using black for shadows with varying transparency looks like the object is actually blocking light.

White: A slight white inset shadow makes the pips look carved into the dice instead of flat prints on top, imitating the light reflections we see in real life.

#000050: Keeping with the family game night and paper theme, many pens are a dark blue colour. Matched with the Kalam font, it is more convincing that the scores are written and not computer printed.

#fcf7eb: Dice that have been used for a while are slightly off-white. This gives them the aged look most people are familiar with.

#F9FBFF: Specifying the paper background colour lets the paper image blend slightly, so it has both the texture of the image and the slight off-white of old paper. It differs from the dice colour because paper and dice discolour differently.

Background

The background is a picture of a table, again to give the family game night vibe.

Fonts

Fonts
Use Font Style
Main/scorecard Inter Default
Points Kalam Default, dark blue
Reasoning

Inter: Inter is a fairly generic font, which makes it more believable that a family went through all their original Yahtzee sheets and had to print more they found on the internet.

Kalam: Kalam is meant to look like handwriting. In dark blue for the points, it is more convincing that a game is being played and the scores are being written down as it goes.

Design Comments

Overall Layout

I chose to keep as much of the content as possible looking like real objects, to give the illusion of the game being played in real life as opposed to on a website.

Possible Interactions and Animations
  • I plan on having the dice animated in some way, likely not 3D rolling, but at least making the pips cycle through a couple of random faces before settling in their final place. I'll likely do this by performing the roll step in JavaScript more times.
  • I plan on slightly moving the held dice in some way to make it clear they are not being rerolled.
  • I plan on having the roll button look like the cup that often comes with Yahtzee, which the user clicks to roll the dice.
  • I plan on trying to animate the scores being written in, as if a person is writing them with a pen. There will also be a pen somewhere on the table.
  • I'd like to animate the roll so the dice are put into the cup, shaken, and thrown back out, but am unsure of the feasibility within the time constraints.

Technical Documentation

The Yatzy game was built in two stages. Assignment #1 produced the design and a static mockup. Assignment #2 added a Node.js and Express server, so the game logic and game state now live on the server and the browser displays the result.

Key Technologies and Techniques

  • Node.js & NPM: Used to run the server-side environment and manage packages such as Express.
  • Express.js: Used to create the server, serve the static public folder, and define the game's routes.
  • Server-side game state: A single gameState object tracks the round, rolls left, dice values, held dice and all scores.
  • JSON & fetch API: Used to exchange data between the browser and the server.
  • JavaScript asynchronous programming: async/await with fetch handles server responses (for example, rolling dice and calculating scores) without freezing the page.
  • jQuery: Used for DOM manipulation and click event handling, such as updating dice faces and attaching listeners to the scorecard boxes.
  • HTML & CSS: Semantic markup and a custom stylesheet reproduce the paper scorecard, dice and table background from the design mockup.
  • JavaScript & CSS animation: Used for the highlight effect on held dice.
  • VS Code: Primary code editor.
  • GitHub: Version control and project tracking for the portfolio repository.

Server Routes

Express routes used by the game
Route Purpose
/roll-dice Rerolls all dice that are not held and decreases the rolls left.
/hold-unhold-dice/:die Toggles whether a die is held.
/calc-score/:box Calculates the score for a scorecard box from the current dice.
/end-round/:table/:roundScore Adds the score, applies the upper bonus, and starts the next round.
/game-state Returns the current game state.
/new-game Resets the game state.
/end-game Returns the final total score.

Code Organization

The project separates its responsibilities across files.

  • Server.js: server, game state and scoring rules.
  • Dice.js: dice faces, rolling and holding on the page.
  • YahtzeeEngine.js: client helper that requests scores from the server.
  • YahtzeeGame.js: starting a new game and resetting the interface.
  • Mockup.html and styles.css: the page structure and appearance.

How a Roll Works

  1. The player clicks the roll button.
  2. The browser sends a fetch request to /roll-dice.
  3. The server rerolls the dice that are not held and sends back JSON.
  4. jQuery updates the dice faces and the rolls-left counter.

Highlights & Challenges

Highlights

  • Server-client interaction: Using fetch and Express gave the game a clear flow of data between the browser and the server.
  • Asynchronous operations: async/await let dice rolls and score calculations run without interrupting the player.
  • Theme: Realistic dice, a paper scorecard and a handwriting-style font for scores give the "family game night" feel.
  • Responsive design: The interface was built to stay usable across screen sizes.

Challenges

  • Migrating from client only to server-client: Migrating from only client side javascript to client-server interaction with Node.js posed a unique challenge. The logic had to be split between the two sides depending on what it was doing, and some parts had to be reworked entirely.
  • Moving logic to the server: Scoring and state had to be reorganized so the server is the single source of truth.
  • Handling varied responses: The roll route can return dice values or a message when no rolls are left, so the client checks the response type before updating the page.
  • Scoring rules: Details such as the full house minimum of 25, the straight checks, and the +35 bonus at 63 points needed careful testing.
  • Resetting the game: A new game has to reset both the server state and the interface (dice, holds, scorecard and end screen).

Future Improvements

  • Use POST requests for actions that change state, instead of GET.
  • Store game state per player session, so several players can use the server at once.
  • Add the cup-shake roll animation from the original design.
  • Now that I understand how to use Node.js and Express.js the entire project could be made more smoothly by starting with these specific technologies instead of adapting existing JavaScript
